# TC-01 · 数据规范（`01-数据规范.md` · 依据定案文档）

> 依据：`docs/design/decisions.md` 定案版本（最高优先级）；契约参考 `01-数据规范.md` §1–§8 与 `02-core.md` §4（parser/Zod/classifyFile）、§2.7（allocateId）。
> 纪律：预期结果可判定（Zod safeParse 的 ok/issues，编号耗尽 `E_SEQ_EXHAUSTED`，id/目录名一致判定）。

---

### TC-01-001 project 必填字段全通过
- **功能点**：`01-数据规范 §1.1` project.md（type/id/name/status/period/tags，`02-core §2.3` ZProject）
- **优先级**：P0（核心路径）
- **类型**：单元
- **前置条件**：无
- **步骤**：1. 构造 frontmatter：type="project", id="proj", name="我的应用", status="active", period=["2026-01-01","2026-12-31"], tags=["frontend"]。2. Zod safeParse（`01-数据规范 §5`）。
- **预期结果**：ok=true，无 issues；name 过 trim 后非空；period 元组 start≤end。

### TC-01-002 project period start>end 非法
- **功能点**：`01-数据规范 §1.1` period 元组 start ≤ end（`02-core §4.4` classifyFile project 判定也含此）
- **优先级**：P0
- **类型**：单元
- **前置条件**：无
- **步骤**：1. period=["2026-12-31","2026-01-01"]，其余字段合法 → safeParse。
- **预月果**：ok=false，issue 在 path ["period"]，报 start 必须 ≤ end。

### TC-01-003 project period 元素缺失/非法
- **功能点**：`01-数据规范 §1.1` period 元素两个，各非空有效 ISO 日期（`02-core §4.3` parse）
- **优先级**：P1
- **类型**：单元
- **前置条件**：无
- **步骤**：1. period=["2026-01-01"]（长度不足）；2. period=["", "2026-12-31"]（空元素）。
- **预期结果**：ok=false，issue 落在 period 字段（tuple 长度/元素校验）。

### TC-01-004 project status/id/name 非法
- **功能点**：`01-数据规范 §1.1` status 枚举；id 符合 §1.5 Slug 正则（`02-core §4.4` 解析失败 → broken parse）
- **优先级**：P0
- **类型**：单元
- **前置条件**：无
- **步骤**：1. status="online"；2. id="a--b"（连续 -）；3. name="   "（空串）。
- **预期结果**：ok=false，三个字段各报错（field=status/id/name）。

### TC-01-005 project tags 重复去重与非空元素

- **优先级**：P1
